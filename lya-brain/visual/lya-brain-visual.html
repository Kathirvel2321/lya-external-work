How LYA thinks

Not a chatbot wrapper. A layered state machine where the language model is the last resort, every fact carries provenance, and saying "I'm not sure" is a correct answer.

01The eight layers

Each layer is a table plus rules — not a subsystem. L1 is RAM, L2/L3/L5 are encrypted SQLite, L4 is the registry, L6 is a function, L7 is a scheduled job. The measured constraint: this laptop has 7.71 GB RAM, i3-1315U, no NPU, so L1–L6 must fit in well under 400 MB and L7 must not run here.

Order shows how a single query travels up the stack

02The ten-step thinking loop

Step 4 is the whole design: if recall already contains the fact, the model has nothing to add except risk. Genuine questions exit before any model is called.

03Where a question actually goes

Most queries never reach a model. The four cheaper things — registry, cache, grounded recall, rule check — must all fail first. Watch the token travel.

04The abstention contract — what "correct" means

Three registers, never blurred. A free model that abandons is safer and more useful than a paid model that invents your mother's birthday.

SAVED from a store (L2 / L3)
  • "Here's what's saved: …"
  • Carries provenance: store, row, timestamp
  • Reliable. Citable. No model involved.
BELIEF model-generated
  • "I believe …"
  • Plausible, unverified
  • Never presented as fact
REFUSAL no grounding
  • "I'm not sure — I don't have that saved."
  • This is the honest register
  • Makes the other two trustworthy
PROVENANCE IS MANDATORY
  every item entering L1 carries  { store, ref, written_at, confidence }
  an item WITHOUT provenance  ->  cannot be used for a factual claim

"what's my brother's name?"
  └─ answered from L3, with provenance
  └─ or "I don't have that saved."
  └─ NEVER from model memory

06L7 — the "sleep" cycle

Runs on the always-on box, never the laptop, only when the laptop is idle. This is where episodic memory becomes durable knowledge.

1  compress stale episodes  ->  facts, with valid_from / valid_to
2  dedupe facts             ->  a typed decision (JEV: duplicate? yes/no + confidence)
3  decay unused RANKING     ->  never delete explicit memories   (D-10)
4  rebuild FTS + vector indexes
5  export a readable Markdown snapshot      <-- the escape hatch
6  emit one metrics line: facts, compacted, index size, failures

07A capability is a plug, not a paragraph

No capability without a matcher, a tier, and a test. A capability without a test is a liability with a nice name.

{
  "name":       "device_health",
  "matcher":    "(how|what).*(cpu|ram|memory|disk|health)",   ← deterministic, no model
  "tier":       "PUBLIC",                                      ← must exist in policy.py
  "fast":       true,                                          ← no model, no network, <100ms
  "timeout_ms": 2000,
  "idempotent": true,
  "egress":     "none",
  "test":       "test_device_health_returns_all_fields"         ← no test = unverified
}

08Where the work happens — three zones

Not more security features. The goal is that when something fails, nothing important is in the same place as the failure.

ZONE A — "HOME" · the laptop
vault (T0) · memory (T1) · biometrics (T2) · policy · audit · approvals
Rules: no generated code · no untrusted content · no scrapers · no publishing
▼ THE BRIDGE — artefacts out · secrets never in ▼
ZONE B — "WORKSHOP" · Oracle VM / WSL2 / sacrificial rig
generated code · scrapers · network tools · ffmpeg renders · browser automation
Rules: NO keys · NO biometrics · NO personal files · assume it WILL be compromised · rebuild < 15 min
▼ ciphertext only ▼
ZONE C — "FOREVER" · runs while the laptop is closed
scheduler · nightly backup · consolidation (L7) · notifications
Rules: ciphertext only · never a key

09The security claim, stated honestly

"Unhackable" does not exist
Anyone who promises it is mistaken or selling something. But the goal underneath is achievable, and it is strong:
COMPROMISE ≠ DISCLOSURE.
An attacker who fully owns the laptop must still be unable to read your top-tier secrets, because the key that opens them is not on the laptop.
Two findings to fix first
W-1 — one key opens everything
security/vault.py:31
secrets, memory, biometrics, logs share one blast radius
W-2 — the vault's own 2nd factor leaves the device
security/auth_wall.py:88-102
audio containing your spoken security word is uploaded to Groq Whisper
Explicitly NOT guaranteed
· live capture while you unlock
· physical coercion
· zero-days in Windows / Python / CPU
· supply-chain compromise upstream
· owner error (passphrase beside the file)
· a resourced state-level adversary
Naming these is not defeatism. A model that claims to defend everything defends nothing, because it cannot say where to spend effort.

10How we prove it works

If a test cannot be written for a claim, the claim does not belong in the document.

OFFLINE / SYNTHETIC
  test_route_never_calls_model        a known command resolves with the model unreachable
  test_answer_is_grounded_or_abstains a fact question with nothing stored -> REFUSAL, not invention
  test_provenance_required            an item without provenance cannot be cited as "Saved"
  test_recall_is_flat                 recall latency flat 100 -> 10,000 rows
  test_write_is_idempotent            the same job step applied twice writes once
  test_validity_interval              a superseded fact is not returned as current

RED TESTS (must FAIL CLOSED)
  R-01  copy .lya + .lya_key to a clean machine      -> T0 decryption FAILS
  R-02  passphrase present, phone factor absent      -> T0 decryption FAILS
  R-06  MCP tool description changed after pinning   -> tool REFUSED
  R-07  instruction hidden in a document             -> treated as data, no tool call
  R-10  grounded payload contains a secret           -> send BLOCKED + audit event
